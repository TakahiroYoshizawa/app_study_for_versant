# Versant スピーキング練習アプリ 要件

## 0. いま欲しいもの

作り方にはこだわらない。HTML は出来上がりを読みやすいという理由であり、フレームワークを禁止する条件ではない。サーバーも最初は要らない。手元で開ければよい。

このアプリを作る理由は、チャットに英文を貼るだけでは足りないからである。欲しいのは次の練習ループである。

1. 各パートの形式で問題を出し、制限時間を管理し、採点する。
2. 問題ごとの正否を残す。間違えた問題にはチェックを付ける。同じ問題に3回連続で正解したら、その問題は理解できたものとする。間違えたらチェックが戻り、連続回数は0に戻る。
3. 問題の英文が、端末の読み上げで確実に再生される。

Gemini は、再話や自由回答のように正解文との一致だけでは採点できないパートのための補助である。アプリの中心には置かない。発音採点も今はやらない。

Part B と見て読むは10問、Part A は1セット（8問）を1セッションにする。セッションの最後に、各問の練習点をまとめて表示する。各問の合格、チェック、3連続は、その場の判定のまま変えない。まとめのあと、利用者が依頼したときだけ、そのセッションの録音と正解文を Gemini に送る。Gemini には、各単語が確かに聞こえるか、余分や言い直しがあるか、気になる発音はどこかを答えさせる。正答数は増やさない。発音の点数は出さない。この結果は合格とチェックを書き換えない。共通のAPIキーは置かない。使う人が自分のキーを貼り、利用料はそのアカウントにかかる。キーは端末にだけ保存する。

いま動いているのは Part A（音読）と Part B（リピート）である。正否、チェック、3連続は両方に入っている。Part A は番号だけを読み上げ、1番から8番の順で進む。他パートも、同じ正否の記録を後から載せる。

以下はパートごとの出題形式と採点のメモである。上の3つと食い違うときは、上の3つを優先する。

---

本書は実装方針の確定版である。採点式、タイマー、開示タイミング、アーキテクチャは、実装中に独自に変えない。変えるときは本書を先に更新する。

点数はすべて練習用の推定であり、Pearson の公式 Versant スコアではない。画面上の点数に、公式スコア、20–80 点スケール、CEFR への換算、という表示を付けない。

問題文はすべてオリジナルで書く。Pearson のサンプル項目、問題集、受験記憶の再現をデータに入れない。

## 1. 目的とスコープ

個人用の英語スピーキング練習アプリである。対象は、日本語話者が Versant と呼ぶことの多い **Versant English Test（スピーキング、約15分、6パート）** の形式を模した練習である。

| パート | 名称 | 問数 | 回答時間 | 開始制限 | 出題中に受験者が受け取るもの |
| --- | --- | --- | --- | --- | --- |
| A | Reading | 8 | 15秒 | 6秒 | 画面上の8文。読む番号は音声 |
| B | Repeat | 16 | 15秒 | 6秒 | 文を音声で1回。画面には出さない |
| C | Short Answer Questions | 24 | 15秒 | 6秒 | 質問を音声で1回。画面には出さない |
| D | Sentence Builds | 10 | 15秒 | 6秒 | 3つの断片を音声で1回。画面には出さない |
| E | Story Retelling | 3 | 30秒 | なし | 短い話を音声で1回。画面には出さない |
| F | Open Questions | 2 | 40秒 | なし | 設問を音声で1回。画面には出さない |

アプリのタイマーは上表の秒数に固定する。本番の公開説明には幅があるため、アプリは「約6秒」を **6000ミリ秒**、「15秒 / 30秒 / 40秒」をそれぞれ **15000 / 30000 / 40000ミリ秒** として扱う。

各パートの本番サブスコア（後述）は、アプリが同じ名前の公式点を出すという意味ではない。アプリが出すのは、そのパートで練習できる技能に対応した **0–100 の練習点** と内訳である。

対象外（この1回だけ書く）: Versant English Placement Test は対象ではない。Placement は9パート（Read Aloud、Repeats、Sentence Builds、Conversations、Typing、Sentence Completion、Dictation、Passage Reconstruction、Summary & Opinion）であり、本書の6パート試験とは別形式である。

v1 の完了単位は、パートを1つずつ練習するセッションである。6パートを休みなく連続する模擬試験は、各パートの進行が揃ったあとの結合であり、初回マイルストーンには入れない。採点式は模擬試験でも本書と同じにする。

## 2. アーキテクチャ

手元のマシンで動かす静的フロントエンドとする。v1 にサーバーは置かない。

- 手書きの HTML を1枚にまとめない。6パート、採点、履歴を分けて保守できるよう、静的フロントエンドアプリとして作る。現在の選択は Vite + React + TypeScript である。
- v1 ではバックエンド、データベース、サーバーレス関数を追加しない。音声認識、読み上げ、タイマー、パート A/B/C/D の採点、履歴は、すべてブラウザ内で完結する（Web Speech API と localStorage）。
- パート E と F で後から使う Gemini は、ブラウザから利用者自身の API キーで直接呼ぶ。キーは localStorage にだけ置き、リポジトリへコミットしない。ソースや設定ファイルへ埋め込まない。
- 最初の実行はローカルである。利用者のマシンで開発サーバーを起動する。本番ビルドは静的ファイルなので、後から Cloudflare Pages、Netlify、GitHub Pages などの静的ホスティングに載せられる。そのデプロイ作業は初回マイルストーンの対象外とする。
- Web Speech API（`speechSynthesis` と Speech Recognition）が使えるブラウザが必須である。想定はデスクトップ版 Chrome である。API が無いブラウザではパートを開始しない。

採点計算は UI から分離した純粋関数にする。音声も localStorage も無い状態で、正解文と文字起こしを渡して同じ点数になることを確認できるようにする。パート B の進行（読み上げ、ビープ、制限時間、確定、開示）を共通の進行にし、他パートは出題内容と採点関数を差し替える。

Gemini の API キーはブラウザの開発者ツールから見える。個人利用ではこれを許容する。共有キーは置かない。キー用の localStorage キーは `versant-study:gemini-api-key` とし、履歴レコードにはコピーしない。

## 3. 全パート共通の機能

### 音声の流れ

各問は次の順で進む。

1. 英語の問題音声を **1回だけ** 再生する。読み上げは `speechSynthesis`、言語は `en-US`、rate は 1.0。再生前に `speechSynthesis.cancel()` する。
2. 問題音声が終わったあと、約200ミリ秒のビープを鳴らす。ビープの終了時刻が回答ウィンドウの開始時刻である。
3. 回答ウィンドウ中にマイク入力を Speech Recognition で文字起こしする。言語は `en-US`、`continuous` と `interimResults` は有効。認識エンジンがウィンドウの途中で止まっても、ウィンドウ終了まで再起動して final 結果を連結する。
4. 可能なら `MediaRecorder` で同じ区間の音声を録る。再生できないコーデックなら、採点は続け、再生ボタンだけ出さない。
5. 確定後、その問の結果を出す。結果画面では、問題音声の再読み上げと、録れていれば自分の回答の再生ができる。
6. 受験者が「次へ」を押して次の問へ進む。結果を自動で飛ばさない。

パート開始時の操作説明は日本語で画面に出す。各問の英語音声は問題本文だけとし、説明ナレーションを毎問は入れない。

回答ウィンドウ中は、問題音声をもう一度再生しない。Part A 以外は、回答ウィンドウ中に問題文を表示しない。

受験者向けに「回答を終える」ボタンを置く。押した時点の文字起こしで確定する。無音の切れ目だけでは確定しない。一時停止で文の続きを切らない。

### タイマー

残り回答時間を秒で表示する。A–D は、発話開始を検知するまで「開始まで残り」も表示し、検知したあとは回答時間だけを残す。

発話開始時刻は、`onspeechstart` と、空でない最初の interim または final のうち、早い方である。開始時刻はウィンドウ開始からのミリ秒とする。

A–D の開始制限: ウィンドウ開始から 6000ミリ秒の時点で発話開始が無いとき、その問を打ち切って次の結果へ進む。追加の猶予は設けない。発話が 6000ミリ秒以内に始まっていれば、合計の回答時間（15秒）まで続ける。開始に成功しても、残り時間はリセットしない。開始が 5.9秒なら、残りは約9秒である。

E と F に開始制限は無い。ウィンドウいっぱいまで待つ。

### 無回答

次のいずれも無回答とする。見出し点は 0。Gemini は呼ばない。

- A–D で、6000ミリ秒以内に発話開始が無い（理由 `no_start`）。
- ウィンドウ終了時点の final 文字起こしが、正規化後に空である（理由 `empty`）。フィラーだけの発話は空と同じである。

### マイク確認

パートを開始する前に確認する。

1. `getUserMedia({ audio: true })` が成功すること。
2. 入力レベルが動くことを短く表示すること。
3. Speech Recognition を起動できること。この確認中の認識結果は捨てる。
4. `speechSynthesis` で短い英語（"Ready."）を再生できること。

マイク拒否、または Speech Recognition が無い場合は開始しない。Chrome のサイト設定でマイクを許可する案内を日本語で出す。読み上げだけ失敗した場合は、隠す文を代わりに表示せず、音声の再試行を出す。Part A の8文は最初から画面にあるので、その表示は続けてよい。番号の読み上げに失敗した問は、その問を開始しない。

### 解答の開示タイミング

初回マイルストーンは、各問の確定直後にその問だけを開示する。パート終了まで正解を隠す連続モードは作らない。

開示するものは、問題文（A は指定番号と該当文）、認識テキスト、見出し点、本書でそのパートに定めた内訳、無回答ならその理由、である。次の問の音声は「次へ」のあとで再生する。

Part A では、回答ウィンドウ開始と同時に指定番号を大きく表示する。8文のうち該当文の強調は、確定後までしない。

### 履歴に残す項目

保存先は localStorage の `versant-study:history`。サーバーへ送らない。音声ブロブは履歴に入れない。音声の再生は、そのセッションのメモリ上だけとする。再読み込み後は点数と文字起こしだけが残る。

履歴はセッション最大50件。超えたら古いセッションから捨てる。`setItem` が失敗しても、画面上の結果は残し、保存できなかった旨を出す。

セッション:

- `id`（UUID）
- `part`（`A`–`F`）
- `startedAt` / `finishedAt`（ISO 8601）
- `aborted`（途中終了なら true）
- `itemCount`
- `meanScore`（下記。出せないときは null）
- `items`（問ごとの結果）

問ごと:

- `itemId`
- `transcript`（連結した final。空なら空文字）
- `latencyMs`（発話開始までのミリ秒。無回答なら null）
- `responseDurationMs`（発話開始から確定まで。開始が無ければ null）
- `noResponse` / `noResponseReason`（`no_start` または `empty` または null）
- `score`（0–100 の整数。採点していないときだけ null）
- `scoreDetail`（パートごとの内訳）
- `geminiStatus`（`not_used` / `ok` / `no_key` / `error` / `invalid_json`）

パートの平均点は、完走したセッションだけ出す。分母はそのパートの出題数。無回答は 0 として入れる。途中終了のセッションは平均を出さず、終わった問の点数だけ見せる。E/F で API キーが無く採点していない問があるとき、平均は採点できた問だけを分子・分母にし、未採点の問数を別に表示する。1問も採点できなければ `meanScore` は null。

平均は `round(sum / count)`。0.5 は切り上げる。

### ブラウザ制約

- 対象は Web Speech API 付きのデスクトップブラウザ。開発と確認の基準は Chrome とする。
- Firefox と Safari では Speech Recognition が使えなければ開始画面で止める。
- 採点式そのものはブラウザ内で計算し、アプリのサーバーは不要である。
- Chrome の Speech Recognition は、ブラウザの実装として音声をブラウザベンダーの認識サービスへ送ることがある。これはアプリのバックエンドではない。オフラインで認識できるとは約束しない。
- 端末の音声認識は音素を測れない。発音点、抑揚点、なまり点は出さない。
- 読み上げ音声の話者は、その環境で取れる `en-US` の声から選ぶ。声の固定はブラウザ依存であり、取れないときにパートを中止しない。
- 画面の言語は日本語。問題文と読み上げは英語。

## 4. 採点の共通方針

3層に分ける。

| 層 | 対象 | 方針 |
| --- | --- | --- |
| ブラウザ内で閉じる | A, B, D のコア点。C のコア点 | 文字起こしと問題データの比較だけ。Gemini は使わない |
| Gemini のテキスト採点 | E と F のコア練習点 | 文字起こし、問題文、採点用メモをテキストで送る。音声ファイルは送らない |
| 採点しない | 全パートの発音。F の「公式の自動点」 | 発音は後回しの任意コメント。F の練習点を公式の自動採点と表示しない |

発音、または音声そのものの解釈を Gemini に頼る機能は、最後の任意機能である。既定はオフ。コメントを出しても、どのパートの見出し点にも加算しない。音素の採点を音声認識の一致率で代用しない。

遅延、話速、発話時間は表示してよい。見出し点の係数には入れない。開始が 3000ミリ秒以上 6000ミリ秒未満のときは「開始が遅い」と表示するだけにし、減点しない。

### 共通の正規化

A/B/C/D は、正解側と認識側の両方に同じ正規化をかけてから比べる。

1. Unicode NFKC。
2. 小文字化する。
3. ハイフンを空白にする（`twenty-one` は `twenty one`）。
4. 次の縮約だけ、トークン全体が一致したとき展開する。`don't` → `do not`、`doesn't` → `does not`、`didn't` → `did not`、`can't` → `cannot`、`won't` → `will not`、`isn't` → `is not`、`aren't` → `are not`、`wasn't` → `was not`、`weren't` → `were not`、`i'm` → `i am`、`you're` → `you are`、`we're` → `we are`、`they're` → `they are`、`i've` → `i have`、`you've` → `you have`、`we've` → `we have`、`they've` → `they have`、`i'll` → `i will`、`you'll` → `you will`、`he'll` → `he will`、`she'll` → `she will`、`we'll` → `we will`、`they'll` → `they will`、`it's` → `it is`、`that's` → `that is`、`what's` → `what is`、`let's` → `let us`、`there's` → `there is`、`here's` → `here is`。所有格の `'s` は展開せず、アポストロフィだけ消す（`tom's` → `toms`）。作問では、`it has` の意味の `it's` を使わない。
5. 上のリスト以外の句読点は空白に変える。
6. 空白で分割し、空トークンを捨てる。
7. 認識側だけ、フィラー `um` `uh` `er` `ah` `hmm` を捨てる。`like` と `well` は本文になり得るので捨てない。
8. 整数トークン 0 以上 100 以下を英語の語に変える。21–99 は `twenty one` のようにハイフン無しの語列にする。101 以上、小数、序数、年号は変換しない。作問でそれらを正解の唯一の形にしない。

冠詞と前置詞は残す。脱落は脱落として数える。

### A/B/D の単語アライメント

正規化後の正解トークン列を T、認識トークン列を H とする。N は T の長さ。N は 1 以上になるよう作問する。

単語を単位にしたレーベンシュタイン距離を取る。一致のコストは 0、挿入・削除・置換は 1。バックトレースから次を数える。

- M: 一致
- S: 置換
- D: 脱落（T にあって対応が無い）
- I: 余分（H にあって対応が無い）

見出しの単語正確率:

`word_accuracy = clamp(1 - (S + D + I) / N, 0, 1)`

見出し点 = `round(100 * word_accuracy)`。0 未満は 0、100 超は 100。余分が多いと 0 に張り付く。

併記する内訳（点には再計算しない）:

- 語順 `order = LCS(T, H) / N`。同一語は出現回数を超えて数えない。
- 脱落率 `D / N`、余分率 `I / N`、置換率 `S / N`。
- 脱落した正解語と、余分な認識語のリスト。

遅延は見出し点に掛けない。

規範例（正規化後、N = 5）。対象文 `she bought two red apples`。

| 認識 | S, D, I | 見出し点 | 語順 LCS/N |
| --- | --- | --- | --- |
| she bought two red apples | 0, 0, 0 | 100 | 1 |
| she bought red apples | 0, 1, 0 | 80 | 0.8 |
| she bought two red apples yesterday | 0, 0, 1 | 80 | 1 |
| yesterday she bought two red apples | 0, 0, 1 | 80 | 1 |
| 空、または無回答 | — | 0 | 0 |

語順が崩れて置換が増えれば見出し点は下がる。語順スコアは、その崩れを受験者に見せるための併記である。

練習の目安（公式の合否ではない）:

| 見出し点 | 目安 |
| --- | --- |
| 90–100 | ほぼその文 |
| 70–89 | 主要語は取れている |
| 40–69 | 部分的 |
| 0–39 | 不足、または無回答 |

## 5. パート別要件

### 5.A Reading

#### 出題

1セット8文。内容がつながる4文の組を2つ置き、番号は 1 から 8 まで通す。2つの組は画面上で分けて見せる。8文は問の最初から見える。

音声は指定番号だけを読む（例: "Number four."）。文そのものは読まない。1セットの中で8文を各1回ずつ聞く。出題順は番号順にしない。同じ文を2回出さない。

受験者は、指定された番号の文をそのまま読む。回答は15秒。開始は6秒以内。

本番でこのパートに付くサブスコアは発音と流暢さである。文が見えているので、内容面は「指定の文を読んだか」である。アプリがその公式サブスコアを出すわけではない。

#### アプリ機能

- 8文と組の区切りを、セットのあいだ表示し続ける。
- ウィンドウ開始時に指定番号を大きく出す。該当文は強調しない。
- 指定番号の音声が失敗した問は開始しない。
- 確定後に、指定文、認識テキスト、差分、見出し点を出す。

#### 採点

入力は、指定された1文と、その問の文字起こし。Gemini は使わない。

アルゴリズムは「4. 採点の共通方針」の単語アライメント。比べる相手は指定文だけとする。8文のうち点が一番高い文を採用しない。

出す指標:

- 見出し点（単語正確率、0–100）
- M, S, D, I、語順、脱落語、余分語
- `latencyMs`。点には入れない
- 参考診断 `readOtherSentence`。他の7文のいずれかの `(S+D+I)/N` が、指定文のそれより 0.3 以上小さいとき true。診断は見出し点を変えない

出さない指標:

- 発音、流暢さの公式サブスコア、話速を点にしたもの
- Gemini のコメント（コア点）
- 20–80 への換算

無回答は 0 点。

#### 記録

共通の問レコードに加え、`scoreDetail` へ `targetSentenceId`、`M`、`S`、`D`、`I`、`order`、`omissions`、`extras`、`readOtherSentence` を入れる。`geminiStatus` は `not_used`。

#### 問題データの形

1セットが1つのデータである。

- `id`
- `groups`: 長さ2。各要素は `sentences` 長さ4
- 各文: `n`（1–8 の一意な整数）、`text`（英語。読み上げ用の句読点を含んでよい。採点前に正規化する）
- `askOrder`: 1–8 の順列。長さ8

作問: 各組の4文は同じ場面でつながるように書く。語数の指定は無い。番号を声に出しただけでは文が完成しない、独立した文にする。

### 5.B Repeat

このパートを最初に完成する。進行中の実装は本書の採点式に合わせる。

#### 出題

16文。1回だけ聞き、画面には出さない。語数はおおよそ3語から15語へ、セットの中で難度が上がるように並べる。聞こえた文をそのまま繰り返す。回答は15秒。開始は6秒以内。

本番のサブスコアは文の再現（sentence mastery）、流暢さ、発音である。アプリが再現として採点するのは、正解文との単語アライメントである。流暢さと発音の公式サブスコアは出さない。

#### アプリ機能

- 回答ウィンドウ中、文を表示しない。進捗（例: 3 / 16）と残り時間だけ出してよい。
- 確定後まで正解文を出さない。
- 16問が既定。動作確認のために先頭 n 問だけ回す場合も、採点式は同じにする。

#### 採点

入力は、その問の正解文と文字起こし。Gemini は使わない。発音点は出さない。

アルゴリズムは共通の単語アライメントを、その1文に対して1回取る。

出す指標:

- 見出し点（単語正確率、0–100）
- 語順 `order`
- 脱落（件数、率、語リスト）
- 余分（件数、率、語リスト）
- 置換（件数、率）
- `latencyMs`（併記のみ）

出さない指標:

- 発音、音素、なまり
- 流暢さの公式サブスコア。話速を表示してもよいが、見出し点に掛けない
- Gemini による採点とコメント

無回答は 0 点。

練習の目安は、共通方針の 90 / 70 / 40 の帯を使う。

#### 記録

`scoreDetail` に `M`、`S`、`D`、`I`、`order`、`omissionRate`、`extraRate`、`omissions`、`extras` を入れる。`geminiStatus` は `not_used`。正解文は `itemId` から問題データを引いて表示し、履歴に全文を重複保存しなくてよい。

#### 問題データの形

- `id`
- `target`（英語の1文。画面の初期状態では隠す。TTS はこの文字列を1回読む）
- `wordCount`（正規化前の目安。3–15）
- `orderInSet`（1–16。セット内で語数が減らない並び）

作問: 前の問より明らかに短い文を後ろに置かない。固有名詞の知識が無いと復唱できない文にしない。

### 5.C Short Answer Questions

#### 出題

24問。質問を1回だけ聞き、画面には出さない。答えは1語、または短い句。回答は15秒。開始は6秒以内。

質問は、その文だけで解ける日常の論理、時刻、数、順序にする。雑学、時事、固有の知識を問わない。

本番のサブスコアは語彙である。アプリは、許容回答の集合に入ったかを語彙練習の正誤として扱う。

#### アプリ機能

- 回答ウィンドウ中は質問文を出さない。
- 確定後に、質問、認識テキスト、許容回答、正誤を出す。
- 24問が既定。

#### 採点

入力は、正規化した文字起こしと、その問の許容回答（同じ正規化をかけたもの）。Gemini は使わない。単語アライメントは使わない。部分点は付けない。

判定:

- 正規化後の認識列を空白で連結した文字列が、許容回答のいずれかの連結文字列と完全一致すれば正解。見出し点 100。
- それ以外は不正解。見出し点 0。
- 無回答は 0。

近い答えを赤字で見せてもよい。見せても点は 0 のままである。

数字は正規化の 0–100 変換に任せる。許容回答には、作問者が認める語形をすべて書く（例: 時刻の言い方のゆれ）。変換表をこの場で増やさない。

出す指標: 正誤、見出し点 0 または 100、`latencyMs`（併記のみ）、認識テキスト。

出さない指標: 部分点、発音、文のうまさ、Gemini の採点。

パート平均は 100 × 正解数 / 24。無回答は不正解として分母に残す。

#### 記録

`scoreDetail` に `correct`（boolean）、`matchedAnswer`（一致した許容回答。不一致なら null）を入れる。`geminiStatus` は `not_used`。

#### 問題データの形

- `id`
- `question`（英語。TTS で1回。画面の初期状態では隠す）
- `acceptableAnswers`（1件以上の英語文字列。正規化後に一致すればどれでも正解）
- `answerType`（`word` または `phrase`）
- `skill`（`time` / `number` / `sequence` / `everyday_logic`）

作問: 質問の外の知識が要る問を入れない。許容回答は、その質問の論理的な答えに限る。綴りのゆれを無限に増やさない。

### 5.D Sentence Builds

#### 出題

10問。短い句を3つ、文法的ではない順で、音声だけ1回流す。画面には出さない。受験者は、それらを並べ替えて1つの文法的な文として話す。回答は15秒。開始は6秒以内。

本番のサブスコアは、文の再現、語彙、流暢さ、発音である。アプリのコア点は、許容される完成文との単語アライメントである。

#### アプリ機能

- 3つの句のあいだに約400ミリ秒の無音を入れて、保存した順で1回読む。番号や "phrase one" は付けない。
- 回答ウィンドウ中は句も完成文も出さない。
- 確定後に、聞いた順の3句、採用した完成文、差分、見出し点を出す。

#### 採点

入力は文字起こしと `acceptableSentences`。Gemini は使わない。

各許容文に共通の単語アライメントをかけ、見出し点が最大の文を採用する。同点なら語順 `order` が大きい方。許容文が複数あるときも平均しない。

出す指標は B と同じ（見出し点、語順、脱落、余分、置換、遅延の併記）。加えて、採用した文の `acceptedIndex` と、3句それぞれの内容語が採用文側の一致に含まれたか（`chunksCovered`: 長さ3の boolean）。句の欠落表示は診断であり、見出し点の式は変えない。見出し点は採用文に対する単語正確率だけである。

出さない指標: 発音、公式の流暢さ、Gemini。

無回答は 0 点。目安の帯は A/B と同じ。

#### 記録

`scoreDetail` に B のフィールドと、`acceptedIndex`、`chunksCovered` を入れる。`geminiStatus` は `not_used`。

#### 問題データの形

- `id`
- `chunks`: 長さ3の文字列。配列の順が再生順（意図的に崩した順）
- `acceptableSentences`: 1件以上。文法的に認められる完成文。通常は1件。どちらも文法的なときだけ2件目を書く

作問: 3句を繋げると、許容文の語が過不足なく出るものとする。句の途中で単語を増やして完成させる問にしない。

### 5.E Story Retelling

#### 出題

短い話を3本。それぞれ1回だけ聞き、話しているあいだは文字を出さない。自分の言葉で、できるだけ細部を残して話し直す。逐語の復唱が目的ではない。回答は30秒。開始の6秒ルールは無い。

本番の内容点は、話との意味の重なりである。本番のサブスコアは、文の再現、語彙、流暢さ、発音である。アプリは意味の重なりを Gemini のテキスト採点で練習点にし、発音は出さない。

#### アプリ機能

- 回答ウィンドウ中は物語を出さない。
- 空の文字起こしでは Gemini を呼ばない。
- API キーが無い、通信に失敗した、JSON が不正、のいずれでも、文字起こしとタイミングは保存する。見出し点は出さず、状態を表示する。
- 結果画面に「再採点」ボタンを1つ置く。自動では再送しない。

#### 採点

入力はテキストだけ: 物語、キーポイント配列、文字起こし。音声は送らない。モデルは、実装時に Google AI Studio の無料枠で使えるテキスト生成モデルを1つ選び、定数として一箇所に書く。音声入力やマルチモーダル用のモデルは選ばない。呼び出しはブラウザから Generative Language API へ直接行う。

プロンプトに必ず入れる条件:

- 練習採点であり、公式 Versant スコアは付けない。
- 渡された文字起こしだけを材料にする。文字起こしに無い出来事を補わない。
- 同じ文の復唱を要求しない。キーポイントの意味が残っていれば、その点は達成とする。
- 指定の JSON 以外を返さない。
- `practice_note_ja` は日本語で、外したキーポイントが分かるように書く。

返す JSON:

```json
{
  "key_points": [true, false, true],
  "sentence_mastery": 3,
  "vocabulary": 3,
  "practice_note_ja": "日本語の短評"
}
```

`key_points` の長さは、その問のキーポイント数 K と一致しなければならない。各要素は boolean。`sentence_mastery` と `vocabulary` は 0 以上 4 以下の整数。

意味:

| 値 | sentence_mastery | vocabulary |
| --- | --- | --- |
| 0 | 文として成り立っていない、または無回答 | 話の内容語がほぼ無い |
| 1 | 語の羅列が中心 | ごく一部の内容語 |
| 2 | 文はあるが不完全なものが多い | 半分程度の内容語 |
| 3 | おおむね文で話せている | 必要な内容語の大部分 |
| 4 | 聞き手が追えるまとまった文 | 話の内容を言う語が足りている |

内容点はモデルに直接出させない。`content_coverage = round(4 * (true の個数) / K)`。K は 1 以上。

見出し点 = `round(100 * (0.5 * content_coverage + 0.25 * sentence_mastery + 0.25 * vocabulary) / 4)`。

必須キーの欠落、長さの不一致、範囲外の数は `invalid_json`。その問の見出し点は null。生の散文を点数に読み替えない。

出す指標: 見出し点、`content_coverage`、達成したキーポイント、外したキーポイント、`sentence_mastery`、`vocabulary`、日本語の短評、`latencyMs`（併記のみ）。

出さない指標: 逐語の単語正確率を見出し点にすること、発音、音声を送ったうえでの評価、公式サブスコア。

無回答は Gemini を呼ばず 0 点。`geminiStatus` は `not_used`、`score` は 0。

目安の帯は A/B の 90 / 70 / 40 を流用してよい。帯の名前は「練習の目安」とする。

#### 記録

`scoreDetail` に `contentCoverage`、`keyPointHits`（boolean 配列）、`sentenceMastery`、`vocabulary`、`practiceNoteJa` を入れる。キーが無いときは `geminiStatus = no_key` かつ `score = null`。通信失敗は `error`、JSON 不正は `invalid_json`。

#### 問題データの形

- `id`
- `story`（英語。TTS で1回。回答中は隠す。読み上げがおおよそ30秒以内に終わる長さ）
- `keyPoints`: 4個以上8個以下の短い英語句。採点者が数える事実。物語に実際にある事実だけを書く

作問: キーポイントは固有の雑学ではなく、その音声を聞いていれば言える事実にする。

### 5.F Open Questions

#### 出題

設問は2問。描写を求めるもの、または意見と理由を求めるもの。音声で1回。回答中は文を出さない。回答は40秒。開始の6秒ルールは無い。

本番ではこのパートを自動採点しない。音声は人の採点者が聞くために残る。アプリは練習フィードバックを出してよい。その数字を、本番と同じ自動スコアとしては表示しない。ラベルは「練習フィードバック（本番では自動採点されない）」とする。

#### アプリ機能

E と同じ制約で Gemini を使う。キーが無いときは文字起こしだけ残す。空の文字起こしでは API を呼ばない。再採点は手動の1ボタン。

#### 採点

入力はテキストだけ: 設問、`promptType`、`requiresReason`、文字起こし。音声は送らない。モデルの選び方は E と同じ定数でよい。

プロンプトに必ず入れる条件:

- 本番では自動採点されないパートへの、練習フィードバックである。
- 公式スコアは付けない。
- 描写なら具体性、意見なら設問への答えと理由の有無を見る。
- 意見の賛否や、外部知識の正しさでは減点しない。
- 指定の JSON 以外を返さない。
- `practice_note_ja` は日本語。

返す JSON:

```json
{
  "answered_prompt": true,
  "reason_present": true,
  "task_completion": 3,
  "vocabulary": 3,
  "coherence": 3,
  "practice_note_ja": "日本語の短評"
}
```

`task_completion`、`vocabulary`、`coherence` は 0 以上 4 以下の整数。boolean が欠ける、または数値が範囲外なら `invalid_json`。

アプリ側で上書きする規則:

- `answered_prompt` が false なら `task_completion` を 0 にする。
- その問の `requiresReason` が true で、`reason_present` が false なら、`task_completion` を最大 2 に抑える。

| 値 | task_completion | vocabulary | coherence |
| --- | --- | --- | --- |
| 0 | 設問に答えていない | 内容語がほぼ無い | 語句がつながらない |
| 1 | 話題に触れただけ | ごく限られた語 | ところどころつながる |
| 2 | 答えはあるが理由または具体が弱い | 最低限の語 | 大筋は追える |
| 3 | 描写または意見と理由が揃っている | 場面に合う語がある | まとまって聞ける |
| 4 | 40秒の練習として具体が足りている | 同じ語の繰り返しに頼っていない | 最初から最後まで一貫している |

見出し点 = `round(100 * (0.5 * task_completion + 0.25 * vocabulary + 0.25 * coherence) / 4)`。上書き後の `task_completion` を使う。

出す指標: 練習フィードバックの見出し点、上書き後の `task_completion`、`reason_present`、`vocabulary`、`coherence`、日本語の短評、遅延の併記。

出さない指標: 公式の自動スコアという表示、発音、音声の送信、単語の逐語一致。

無回答は API を呼ばず、練習点 0、`geminiStatus` は `not_used`。

#### 記録

`scoreDetail` に `answeredPrompt`、`reasonPresent`、`taskCompletion`（上書き後）、`vocabulary`、`coherence`、`practiceNoteJa` を入れる。`geminiStatus` の意味は E と同じ。

#### 問題データの形

- `id`
- `prompt`（英語。TTS で1回。回答中は隠す）
- `promptType`（`description` または `opinion`）
- `requiresReason`（opinion は true。description は false でよい）

作問: 40秒で話し切れる日常の話題にする。専門知識が無いと答えられない設問にしない。

## 6. 実装順

1. **B を最初に完成する（進行中）。** 共通の進行、マイク確認、15秒と6秒、単語アライメント、各問直後の開示、localStorage の履歴、自分の音声のセッション内再生を、B で固める。
2. **次は A と D。** 採点は B と同じ単語アライメントである。A は画面上の8文と指定番号、比べる相手は指定文だけ、という差がある。D は許容文が複数あり得るので、見出し点が最大の文を採用する。
3. **C。** 許容回答の集合との完全一致。部分点とアライメントは使わない。
4. **E と F。** 文字起こしを Gemini にテキストで渡す。音声はコア採点に送らない。キーは利用者自身のものを localStorage に置く。
5. **発音コメントは最後の任意機能。** Gemini に音声を渡してコメントを得ることはできる。既定はオフ。コメントはコア点に加算しない。A–D の見出し点は、この機能が無くても完成とみなす。

初回マイルストーンに入れないもの: 静的ホスティングへのデプロイ、サーバー、6パート連続の模擬試験、発音のコア採点、公式スケールへの換算。
